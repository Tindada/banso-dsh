# 优化 TODO

- [ ] **主 agent 与提取模型的信息传递及职责边界**：研究主 agent 提供的任务信息、focus 与提取模型工作范围之间的关系，在保留压缩收益的同时，减少对可能改变研究路径的信息的过滤。四轮 GISA 第 5 题中，两次 extract 抓取的正文均包含可用的 HTML 表格入口，但因 focus 限定为 CSV 下载，相关入口未进入提取证据；direct_002 利用了该入口成功取数。此观察作为后续研究线索，具体方案待定。
- [ ] **超长网页/文本的处理策略与宿主能力适配**：当前 `web_read` 的 `direct` 默认在 `100,000` 字符处截断并提示改用 `extract`，而 `extract` 默认受 `maxInputBytes = 200,000` 字节限制，导致超过 200 KB 的页面出现处理断层（`banso_60_001_merged` 中 4 次 `direct` 截断均未改用 `extract` 且其中 3 页超过 200 KB，另有 1 页 1.3 MB 的 JSON 直接调 `extract` 触发超限报错）。后续需按定位选择方案：作为插件接入已有 DSH Agent 时，优先适配宿主 `spill` + `read`/`grep`（需避免 `maxDirectChars` 先截断导致落盘残缺，并留意单行大 JSON 的行截断问题）；若兼顾无文件工具且需隔离宿主机的独立模式，可在 `banso-materials` 内补充受管材料的分段/关键词检索或 `extract` 分块提取。具体方案待定。
- [ ] **域名失败反馈与研究预算策略解耦**：当前 `researchBudget` 将搜索、成功阅读与 404/5xx 失败混在同一额度内计数，且模型无法区分单路径 404 与整站不可达（`banso_60_002_nobudget` 中部分题目在同域名连续撞墙数十次，而预算 30 又在重型 table 题上过早触顶）。后续可在 `banso-materials` 中补充域名级失败计数提示，并评估“网络/404 失败不扣或折半扣预算”及更合适的默认预算上限。具体方案待定。
- [ ] **长链路上下文治理（`web_search` 累积与重复变体页去重）**：`banso_60_002_nobudget` 全盘加权上下文中，`web_search` 结果占 40.8%（部分死磕题高达 72%–79%），另有不同变体 URL 拉回高度相似正文（如 Case 146）。后续可分步评估：① URL 剥离 `#fragment` 与按 `finalUrl`/正文哈希做安全去重；② 搜索重复命中 `S#` 时的片段瘦身；③ 长探索任务结合 DSH `compaction` 或子研究隔离（`subagent`）折叠早期试错轨迹。具体方案待定。
